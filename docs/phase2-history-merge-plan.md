**合并策略**：保留每组信息最全的一条作为主记录，其余条目的**独有信息追加到主记录的对应字段**，
然后将被合并的记录置为终态（商机 `已放弃` / 选题 `已放弃`），**不物理删除**——保留可追溯性。

> 为什么用「已放弃」而不是 `DELETE`：
> 1. 任务书禁止「删除历史商机与选题」；
> 2. 保留被合并记录，可事后核对合并是否正确；
> 3. 详情页仍可查。

## 3. 合并后的字段拼接规则

### 商机

| 字段 | 规则 |
|---|---|
| `title` | 保留主记录原值，不改 |
| `description` | 主记录为空时取最长的非空值；主记录非空但明显更短时，取最长值（本次所有组主记录 desc 都最长，无需拼接） |
| `category` | 保留主记录原值（各组内一致） |
| `notes` | 主记录 notes + 追加合并来源的判断依据，格式：`{主记录notes}\n【合并自 #{id}】{被合并记录notes去掉前缀}` |
| `action_plan` | **不修改**（全为空） |
| `status` | 被合并记录 → `已放弃`；主记录 → 保持 `待研究` |
| `source_report_date` | 保留主记录原值 |

### 选题

| 字段 | 规则 |
|---|---|
| `title` | 保留主记录原值 |
| `angle` | 主记录 angle + 追加被合并记录的角度（用 `｜` 分隔），形如 `{主记录angle}｜备选角度：{被合并angle}` |
| `source_material` | 取**并集**（按 `；` 拼接去重） |
| `reference_visuals` | 取**并集**（按换行拼接去重） |
| `value_score` | 取**组内最高分** |
| `status` | 被合并记录 → `已放弃`；主记录 → 保持 `待制作` |
| `report_date` | 保留主记录原值（全部同为 2026-11-06） |

## 5. 执行方式

在 Agent B 的 `lib/dedup.ts` 就绪后，由主控编写一次性脚本执行合并：
- 脚本放在 `scripts/merge-duplicates.ts`（**主控独占目录**，不入库时可选择不入 Git）
- 先 `--dry-run` 打印将要执行的每条 SQL，人工核对
- 再实际执行
- 执行后立刻核对行数与合并结果，抽样检查 2-3 条记录
