# 更新计划：LLM 切换为 MiniMax 后的适配改造

> 创建时间：2026-11-06 19:55
> 状态：**待执行**（等阶段 1 收尾验收后一起改）
> 触发事件：用户手动将 n8n 中 3 个 LLM 节点从 DeepSeek 切换为 `MiniMax-M3.1-Flash`

---

## 一、背景与根因

### 1.1 现象
首页「今日情报」三个板块全部解析失败：
- 今日核心判断 → 显示「暂不可解析」
- 今日 AI 头条 → 只有标题，无概要、无链接、不可点击
- 今日趋势 → 显示「暂不可解析」
- 商业机会（日报内板块）→ 显示「暂不可解析」

### 1.2 根因（已核实，非猜测）

**前端解析器按 DeepSeek 的输出格式写死，MiniMax 的 Markdown 排版习惯不同。**

| 项目 | DeepSeek（解析器预期） | MiniMax（实际输出） | 结果 |
|---|---|---|---|
| 字段冒号位置 | `- **核心事实**：内容`（冒号在加粗**外**） | `- **核心事实：** 内容`（冒号在加粗**内**） | 正则 `\*\*核心事实\*\*[：:]` 匹配失败 → 所有字段为空 |
| 核心判断条目 | 编号列表 `1. xxx` | 无编号散文段落（每行一段） | `parseOrderedListItems` 返回 0 条 |
| 趋势条目 | 有序列表 `1. **标题**` | 三级标题 `### 1. 标题` | `parseTrends` 返回 0 条 |
| 机会条目 | 有序列表 `1. **标题**` | 三级标题 `### 1. 标题` | `parseOpportunities` 返回 0 条 |

### 1.3 影响范围（已核实）

工作流 `ZtIAVVtWmcPLXywX`（CR-01 每日 AI 情报采集）现有 3 个 LLM 节点，**全部**已切换为 MiniMax：

| 节点名 | 用途 | 模型 | 凭据 |
|---|---|---|---|
| `Basic LLM Chain` | 生成日报正文（主链） | MiniMax-M3.1-Flash | MiniMax account |
| `选题提取 LLM` | 阶段 1 选题提取 | MiniMax-M3.1-Flash | MiniMax account |
| `商机分析 LLM` | 阶段 1 商机分析 | MiniMax-M3.1-Flash | MiniMax account |

三个 chainLlm 节点的 `text` 参数均已带 `=` 前缀（表达式渲染正常），**问题纯粹在输出格式差异**。

### 1.4 不受影响的部分
- `topic_ideas` 表（选题）与 `opportunities` 表（商机草稿）是**结构化数据**，由 Code 节点容错解析 JSON 后写入，不依赖 Markdown 格式 → 阶段 1 功能实际可用
- 首页第三栏「商业机会」显示的是**日报内的 Markdown 板块**（解析失败），与 `/opportunities` 页面的结构化商机是两套东西

## 二、改造方案（双管齐下）

### 方案 A：前端解析器容错（治标，立刻见效）

**文件**：`lib/markdown-parser.ts`

1. **字段正则兼容冒号内外两种写法**
   现有：`/^\s*-\s*\*\*(.+?)\*\*[：:]\s*(.*)/`
   改为：`/^\s*-\s*\*\*(.+?)\*\*\s*[：:]\s*(.*)/`（允许冒号被包在加粗内）
   - 需同步处理 key 尾部残留冒号：匹配后 `key.replace(/[：:]\s*$/, "")`
   - 风险：`(.*)` 贪婪匹配可能吃掉下一行内容 → 需限制为**单行**（不跨行）

2. **核心判断兼容散文段落**
   当前只走 `parseOrderedListItems`。需增加：章节内若无编号列表，则把非空段落按「空行/连续换行」切分为独立条目
   - 需过滤 `> **信息边界说明：**` 这类引用块（今日日报第 8 行有一段引用说明，不应进核心判断）

3. **趋势/机会兼容 `### N. 标题` 格式**
   当章节内条目以 `###` 开头时，按 `###` 切块，取首行为标题、块内字段按方案 A 的新正则提取

4. **头条「概要」缺失的兜底**
   即使字段解析失败，标题 + 原文链接也应可见。当前 `HeadlineCard` 组件需检查：解析不到 `link` 时是否退化显示、是否有 coreFact 缺失时的占位

5. **兜底可见性**
   任一板块解析为 0 条时，除「暂不可解析」外，**至少显示章节原文首段**，避免用户以为系统坏了

### 方案 B：生成端格式约束（治本，保证每天稳定）

**位置**：n8n 工作流中 `Basic LLM Chain` 节点的 prompt

1. 在 prompt 中加入**固定格式 few-shot 示例**（正例 + 反例），明确要求：
   - 核心判断用编号列表 `1. `
   - 头条字段冒号在加粗**外**：`- **核心事实**：...`
   - 趋势/机会用编号列表，**不要**用 `###` 三级标题
2. **增加格式校验节点**：在 `格式化数据` 与 `If` 之间插入校验 Code 节点，检查四大板块是否都能被预期规则解析；不通过则抛错走现有失败分支（落 `report_failures`），并可重试一次
3. 考虑给 `选题提取 LLM` / `商机分析 LLM` 的 JSON 输出也加格式约束（目前靠 Code 节点容错，已够用，可选）
