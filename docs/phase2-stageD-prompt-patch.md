# 阶段 D · 日报 prompt 格式约束补丁

> 用途：施工项 3。插入到 n8n `Basic LLM Chain` 节点的 prompt 中，
> 位置为 `【输出格式】` 段落之后、`【重要】` 段落之前。
> 目标：消除「格式靠运气」的结构性缺陷，让不同 LLM 产出同构输出。

## 为什么必须加

现状 prompt 只规定了 6 个章节标题，**完全没有规定条目内部的字段格式**。
这是 11-06 首页三栏全线「暂不可解析」的根本原因 ——
不是模型能力问题，是需求没说清楚。

具体表现（实测两个真实样本）：

| 项目 | DeepSeek 输出 | MiniMax 输出 | 解析器期望 |
|---|---|---|---|
| 头条字段冒号位置 | `- **核心事实**：内容` | `- **核心事实：** 内容` | 只认前者 |
| 趋势/机会条目 | `1. **标题**` | `### 1. 标题` | 只认前者 |
| 趋势子字段 | 有 `- 判断依据：` | **无** | 需要它 |
| 机会子字段 | 有 `- 机会来源：` | **无** | 需要它 |

## 补丁内容（原文插入）

```
【条目格式约定】
以下格式必须严格遵守，否则下游解析会失败：

1. 核心判断使用编号列表，每条写成一行，格式为：
   1. **一句话核心结论**：展开说明
   （不要写成不带编号的散文段落）

2. 今日必读头条用三级标题分条，标题行格式为：
   ### 1. 新闻标题
   标题下方逐行列出字段，每个字段独占一行，格式为：
   - **来源及发布时间**：来源名称；时间
   - **核心事实**：客观事实陈述
   - **深度解读**：你的分析（可标注「（观点）」）
   - **对行业的影响**：影响分析
   - **原文链接**：完整 URL
   ⚠️ 冒号必须写在加粗之外，写成 `- **核心事实**：内容`；
      不要写成 `- **核心事实：** 内容`。

3. 行业趋势观察用编号列表，每条写成三行，格式为：
   1. **趋势标题**
      - 判断依据：日报中的具体事实（公司动作、产品发布、数据、政策等）
      - 观点：你的判断
   ⚠️ 「判断依据」和「观点」两个子字段必须都写，不能省略。

4. 开发者与创业者机会用编号列表，每条写成四行，格式为：
   1. **机会标题**
      - 机会来源：日报中的具体事实
      - 实现方向：怎么做
      - 潜在价值：为什么值得做
   ⚠️ 「机会来源」「实现方向」「潜在价值」三个子字段必须都写，不能省略。

5. 标点统一：中文内容使用中文全角标点，冒号统一用「：」，
   不要中英文标点混用，不要用半角冒号。

6. 重点领域动态（第三章）的每个子领域，用无序列表列出条目，格式为：
   - **条目标题**：一句话说明。观点：你的判断。链接：完整 URL
```

## 配套的结构校验（施工项 4）

prompt 约束是「软约束」，模型不一定 100% 遵守。
因此 `格式化数据` 节点要同步增强校验，把字段别名表带进去：

```js
// 与 TS 侧 lib/markdown-parser.ts 的别名表保持一致
const FIELD_ALIASES = {
  source: ["来源及发布时间", "来源", "来源和时间"],
  coreFact: ["核心事实", "事实"],
  deepAnalysis: ["深度解读", "深度分析", "解读"],
  impact: ["对行业的影响", "行业影响", "影响"],
  link: ["原文链接", "链接"],
};

// 统计有多少条头条真正解析出了 source + coreFact + link
function countHeadlinesWithFields(markdown) {
  const blocks = markdown.split(/^###\s+/m).filter((s) => s.trim());
  let ok = 0;
  for (const block of blocks) {
    const found = {};
    for (const line of block.split("\n")) {
      // 冒号在加粗外：- **核心事实**：内容
      let m = line.match(/^\s*-\s*\*\*(.+?)\*\*[：:]\s*(.*)/);
      // 冒号在加粗内：- **核心事实：** 内容
      if (!m) m = line.match(/^\s*-\s*\*\*(.+?)[：:]\*\*\s*(.*)/);
      if (!m) continue;
      const key = m[1].trim();
      for (const [field, aliases] of Object.entries(FIELD_ALIASES)) {
        if (aliases.includes(key)) found[field] = true;
      }
    }
    if (found.source && found.coreFact && found.link) ok++;
  }
  return ok;
}
```

新增两个 validation 字段：

```js
validation.headlines_with_fields = countHeadlinesWithFields(markdown);
validation.headlines_field_coverage =
  headlineCount > 0 ? validation.headlines_with_fields / headlineCount : 0;
```

**注意**：这两个字段是**新增**，现有 `If` 节点的判定条件
（`has_content && has_core_judgment && has_headlines && has_trends && has_opportunities &&
markdown_length > 1000 && total_articles > 0`）**保持不变**。

理由：任务书明确禁止「更换 LLM 服务商或模型」以外的过度改动，
而收紧 If 条件会导致日报频繁走失败兜底，反而降低产出。
`headlines_field_coverage` 先作为**观测指标**记录在 `validation` 里，
供人看和监控用，不参与阻断。

如果后续发现格式漂移率确实高，再考虑把它加进 If 条件 —— 那是阶段 3 的事。

## 验收方式

改完 prompt 后手动执行一次，检查：

1. `daily_reports.validation` 里新增的两个字段有值
2. `headlines_field_coverage` 接近 1.0（字段齐全）
3. 前端首页三栏子字段完整显示
4. `report_failures` 表无新增记录
